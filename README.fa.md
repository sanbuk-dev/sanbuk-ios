# Sanbuk iOS SDK

اس‌دی‌کی رسمی iOS برای [سنبوک](https://sanbuk.com) — نمایش تبلیغ در رسانهٔ ناشر، در مدل CPA.

**[English guide →](README.md)**

> **وضعیت: فقط هسته.** منطق مشترک نوشته و تست شده؛ لایهٔ UI مربوط به iOS هنوز ساخته نشده و چیزی روی CocoaPods یا SPM منتشر نشده. بازار موبایل ایران عمدتاً اندروید است، پس این پکیج عمداً **پشت سر** [sanbuk-android](https://github.com/sanbuk-dev/sanbuk-android) حرکت می‌کند، نه جلوتر از آن.

```bash
swift build
swift run sanbuk-core-tests
```

---

## چه چیزی اینجاست

`SanbukCore` — هر چیزی که تصمیم می‌گیرد، با Swift خالص روی Foundation:

| قطعه | کار |
|---|---|
| `ServeURL` | ساخت درخواست آگهی با کل context موبایل |
| `AdParser` | خواندن پاسخ؛ هیچ ورودی خرابی نمی‌تواند به اپ میزبان نشت کند |
| `ImpressionQueue` | صف آفلاین، محدود به اندازه و سن، با dedupe روی شناسهٔ رویداد |
| `ImpressionURL` | افزودن `eid` که سرور تکراری را با آن می‌شناسد |
| `FrequencyCounters` | شمارش، هرس با پنجرهٔ سرور، بقا بعد از مرگ پروسه |
| `Viewability` | دست‌کم ۵۰٪ پیکسل‌ها برای یک ثانیهٔ پیوسته (MRC) |
| `FullscreenPolicy` | چه وقت اینترستیشیال مجاز است قطع کند و چه وقت بستنش |
| `RewardPolicy` | اینکه آگهی پاداشی واقعاً تماشا شده یا نه |

**۱۰۹ چک، صفر شکست.**

## چرا هسته جداست

همان دلیل اندروید: قاعده‌ای که در لایهٔ پلتفرم بنشیند باید برای هر پلتفرم دوباره نوشته شود، و چون با سرعت‌های متفاوت آپدیت می‌شوند، نسخه‌ها از هم دور می‌افتند. `SanbukCore` تنها پیاده‌سازی «چه باید بشود» است؛ لایهٔ iOS تنها پیاده‌سازی «اینجا چطور دیده می‌شود» خواهد بود.

سود جانبی‌اش این است که هسته هرجا یک toolchain سوییفت باشد ساخته و تست می‌شود.

## چرا تست‌ها یک executable اند

XCTest و swift-testing هر دو با Xcode می‌آیند. هسته‌ای که به هیچ‌چیز جز Foundation وابسته نیست باید روی ماشینی با فقط Command Line Tools — و در ایمیج CI بدون Xcode کامل — قابل راستی‌آزمایی باشد. پس تست‌هایش یک executable ساده با یک هارنس کوچک است. `swift run sanbuk-core-tests` در صورت شکست کد غیرصفر برمی‌گرداند، و پایپ‌لاین همین را می‌خواهد.

وقتی لایهٔ iOS آمد و Xcode به‌هرحال در جریان بود، یک تارگت XCTest می‌تواند کنارش بنشیند — نه به‌جایش.

## زمان همیشه سپری‌شده است، نه تاریخ

هر سیاست میلی‌ثانیه از یک منبع یکنواخت می‌گیرد، نه ساعت دیواری. ساعتی که با تصحیح NTP به عقب بپرد یعنی مدتی که هرگز تمام نمی‌شود؛ و ساعتی که به جلو بپرد یعنی جایزه‌ای که هرکس با ۱۵ ثانیه جلو بردن ساعت گوشی می‌گیرد. مقادیر برگرفته از `DispatchTime`/`CACurrentMediaTime` بدهید، هرگز `Date()`.

## پنج قاعده‌ای که این SDK رویشان ساخته شده

**۱. هرگز نکش، هرگز نمیر.** هیچ خطایی از این SDK نباید به اپ میزبان برسد. بدترین حالت مجاز یک جعبهٔ خالی است.

**۲. هیچ I/O روی ترد اصلی.** گیر کردن هنگام اجرا سریع‌ترین راه حذف‌شدن است.

**۳. تصمیم‌ها سمت سرور می‌مانند.** ماچینگ، pacing، فرکانس‌کپ، بودجه — همه سمت سرور. نسخه‌ای که روی گوشی‌ها رفته ماه‌ها منجمد است؛ هر قاعده‌ای که اینجا سفت شود سال‌ها با ما می‌ماند. `kill` در پاسخ را رعایت کنید: تنها راه بازنشسته‌کردن یک بیلد خراب همان است.

**۴. کلیک مرورگر واقعی را باز می‌کند.** `SFSafariViewController`، هرگز `WKWebView`. سبد کوکی جدا انتساب first-party را می‌شکند، و در یک شبکهٔ CPA یعنی ناشر کار کرده و پولی نمی‌گیرد.

**۵. بدون شناسهٔ تبلیغاتی.** نه IDFA، نه پرامپت ATT. فقط یک شناسهٔ نصب تصادفی و ریست‌شدنی برای فرکانس‌کپ و محدودیت نرخ.
